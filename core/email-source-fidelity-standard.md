# Проверка соответствия модели источнику Figma

## Граница проверки

После заполнения `email-model` и до renderer сравнивается **та же модель**, которая пойдёт в handoff, с независимо снятыми данными конкретных Mobile/Desktop инстансов письма. Допустимость по schema, разрешение contracts, проверка физических файлов и визуальное сравнение — отдельные проверки. Успех одной из них не заменяет остальные.

Проверка не копирует примерный текст из библиотечного компонента и не выводит значения из готовой модели. Из Figma повторно читаются фактические узлы письма. При разногласии фиксируются node ID, поле, viewport и путь модели; модель или Figma не исправляются догадкой.

## Временный вход проверки

Вне папки готового письма создаётся UTF-8 JSON с полями `model`, `readings`, `correspondence`, `authorizedInputs` и `assetEvidence`. Это проверочная трассировка, не новый формат письма и не источник CSS.

- `readings.capture_id`, `file_key`, `captured_at` идентифицируют одно состояние файла. `selection.mobile` и `selection.desktop` содержат точный `root_node_id`, `scope: "full-email"`, `terminal: true`, `truncated: false`. `complete: true` допускается только после проверки полного охвата выбранных ответов и дочерних узлов. Один флаг не служит доказательством полноты.
- `readings.instances` содержит для каждого модельного экземпляра оба конкретных `node_id`, нормализованные `parent_node_id`, `order`, `relation` (`slot`/`nested` и `element_id`) и выбранный `variant_id`. При нормализации сохраняется ссылка на исходный Figma parent/slot; Figma INSTANCE внутри границы изображения не становится модельным экземпляром.
- `readings.fields` содержит все реализационно значимые наблюдаемые поля выбранного охвата: `viewport`, `node_id`, `owner_node_id`, точное `field`, `value` и при наличии `inline_runs`. Текст переносится посимвольно, включая NBSP и явные переносы. `readings.assets` содержит `viewport`, точный `node_id` экспортной границы, `owner_node_id` и непустой `evidence_id`.
- `correspondence.capture_id` и `file_key` совпадают с readings. Его `instances`, `fields` и `assets` связывают каждый model instance/binding/asset contract с фактическим источником. Для Figma field указывается `origin: "figma"`; для адресов и alt, отсутствующих в макете, допустимы только подтверждённые `user` или `policy-derived` inputs с конкретной ссылкой на ввод/правило. Test fixtures не используются в полноценной сборке.
- `assetEvidence` — реальные export receipts существующего handoff с фактическим SHA256 файла. Для source comparison в `mcp_export` дополнительно указываются `capture_id`, `file_key`, `source_node_id`, непустой `evidence_id`; они должны совпасть с наблюдаемым owner и источником экспорта.
- Каждый наблюдаемый экземпляр, field и asset должен быть сопоставлен ровно один раз либо внесён в `readings.exclusions` с точным видом, node/field ID и обоснованием. Исключение относится, например, к декоративному или asset-internal узлу, а не к недостающему контенту. Дубли ключей, неучтённое поле/изображение, чужой owner, другое состояние или неподдержанная inline-семантика дают diagnostic.

Для временного теста отдельного поддерева допускается `scope: "selected-subtrees"` и команда с `--selected-test`. Такой результат подтверждает только выбранные узлы и **не** является прохождением проверки полного письма.

## Запуск и решение

```powershell
node scripts/verify-email-source.mjs <source-evidence.json>
```

Код 0 означает отсутствие найденных расхождений в полном охвате; 1 — typed diagnostics; 2 — невалидный вызов или нечитаемый вход. Шаг `verify-model-source` выдаёт `source-comparison`; `render-email-cli` не начинается при диагностике или неполном evidence. Для теста поддерева добавляется `--selected-test`, но его результат нельзя передавать вместо production `source-comparison`.

Проверка не доказывает сама себя: metadata полноты и нормализация получены от читающего агента, а hash подтверждает байты, не выбор правильного слоя. Спорные узлы повторно читаются непосредственно через Figma MCP, а после рендера выполняется отдельное визуальное сравнение. Исходные MCP-ответы и временные таблицы не коммитятся и не кладутся в папку письма.
