# Стандарт поддержки Figma-библиотеки

Единственная ответственность этого файла — принципы поддержки Figma-библиотеки.

Этот документ задаёт общую дисциплину изменения библиотеки. Он не описывает сборку конкретного письма и не повторяет факты компонентов.

## Источники истины

- Универсальная логика нейминга находится в `data/foundations/figma-naming.yaml` и проверяется его схемой.
- Точная система отступов находится в `data/foundations/spacing.yaml`.
- Факты, свойства, связи, версии и asset-контракты каждого компонента находятся в структурированных компонентных реестрах.
- Граница полного компонентного контракта определена в `core/component-contract-standard.md`.
- Правила компактной Figma Description определены в `core/figma-component-description-standard.md`.
- Человеко-читаемые пояснения к неймингу находятся в `core/figma-component-naming-standard.md`.
- Порядок анализа, согласования и синхронизации изменений задаёт workflow поддержки библиотеки.

## Принципы

- До изменения оценивается влияние на компонент, связанные компоненты, структурированные источники, производные документы и будущий HTML-рендеринг. Пользователю заранее сообщается затронутая область.
- Фактический дизайн в Figma не изменяется без прямого разрешения. Изменение Description не даёт разрешения менять структуру, свойства или организацию компонента.
- Неясное имя не исправляется автоматически. Сначала определяется функция объекта, затем предлагается имя по стандарту, и только после согласования выполняется переименование.
- Значимый суффикс масштаба экспортируемого слоя сохраняется при нормализации имени.
- Точные значения не выводятся из общих принципов: они читаются из Figma и записываются в соответствующий структурированный источник.
- Новый или изменённый компонент проверяется для обеих версий, включая свойства, вложенные связи, текстовые назначения, отступы, ассеты и адаптивное поведение.
- Полное описание компонента хранится в структурированном реестре. Figma Description является компактной производной подсказкой и не служит входом для HTML-рендеринга.
- После изменения синхронизируются только реальные владельцы затронутых данных и их производные представления. Несвязанные файлы и компоненты остаются неизменными.
- Массовое переименование или изменение связей требует отдельной карты воздействия и проверки после применения.

## Граница ответственности

Этот файл не:

- перечисляет компоненты, слои и их идентификаторы;
- хранит точные размеры, токены или свойства;
- задаёт текст конкретной Description;
- определяет этапы сборки письма и экспорта его файлов;
- разрешает автоматическое изменение Figma без анализа воздействия и согласования.

Точные данные принадлежат Figma и структурированным источникам; последовательность работы принадлежит workflow.
