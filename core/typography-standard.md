# Стандарт применения типографики

Единственная ответственность этого файла — принципы применения типографики.

Этот документ объясняет, как использовать уже определённую типографическую систему при работе с библиотекой и HTML-письмом. Он не дублирует каталог стилей и не назначает стили конкретным компонентам.

## Источники истины

- Точные стили, их Figma-названия, параметры и пары версий находятся в `data/foundations/typography.yaml` и проверяются его схемой.
- Назначение стиля конкретному текстовому элементу находится в контракте компонента.
- Фактический текст и выбранный вариант приходят из конкретного инстанса письма.
- Последовательность проверки и синхронизации определяет соответствующий workflow.

## Принципы

- Семантический уровень текста сохраняется между мобильной и десктопной версиями, а точные параметры берутся из соответствующей пары стилей.
- Нельзя выбирать стиль по визуальному сходству, приблизительному размеру или названию слоя. Нужна точная ссылка из контракта.
- Иерархия заголовков, основного текста, подписей и служебного текста должна оставаться различимой после применения фактических значений.
- Размер, межстрочный интервал, насыщенность, выравнивание и семейство шрифта применяются как единый разрешённый набор, а не собираются из разных стилей.
- Резервная цепочка шрифтов применяется вместе с основным шрифтом по структурированному источнику. Наличие fallback не является разрешением заменить основной стиль.
- Высота текстовой области следует содержимому, если компонентный контракт явно не задаёт другое поведение.
- Естественный перенос текста сохраняется. Ручные разрывы допустимы только как подтверждённая часть фактического контента.
- При изменении типографики сначала оценивается влияние на пары версий и потребителей; затем обновляется структурированный источник и зависимые проекции.

## Граница ответственности

Этот файл не:

- содержит перечень точных размеров и названий всех стилей;
- перечисляет компоненты-потребители;
- хранит компонентную геометрию;
- задаёт HTML-разметку текстовых блоков;
- определяет порядок сборки письма.

Точные определения и назначения читаются из foundation-файла и разрешённых компонентных контрактов.
