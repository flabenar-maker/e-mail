# CUPIS: заполнение модели письма и завершение Stage 10

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Routine local tests and visual regression must be delegated to `gpt-5.6-terra` with `medium` reasoning and bounded context.

**Goal:** Собрать два предоставленных пользователем письма существующим renderer из проверенных данных конкретных Figma-инстансов, проверить версионное изменение и завершить Stage 10 без зависимости от истории чата.

**Architecture:** Единственный формат композиции письма — существующий `email-model`. Codex получает факты конкретного письма через Figma MCP, сопоставляет их с разрешёнными контрактами и заполняет модель. Существующие validators, handoff и renderer выполняют проверку и HTML-сборку; evidence переноса данных остаётся отдельным временным материалом проверки. Новый Assembly Manifest, обязательный универсальный Figma compiler и веб-конструктор этим планом не вводятся.

**Tech Stack:** Node.js 24, JSON Schema, YAML/JSON-compatible contracts/workflow, существующий resolver и renderer CLI, Figma MCP, локальная браузерная проверка.

**Spec:** [master design](../specs/2026-08-24-cupis-structured-email-system-design.md), [HTML rendering design](../specs/2026-09-10-cupis-html-rendering-design.md). Уточнение границ заполняющего модель агента выполняется в пакете 1 до технических изменений.

## Global Constraints

- Persistent source и правки системы — только cloud GitHub. Локальный exact-SHA snapshot допускается только как изолированная среда проверки, а не как источник правок.
- Figma читается только через MCP. Этот план не разрешает изменение дизайна, структуры, названий или Description.
- Данные компонентов не исправляются ради совпадения теста. Доказанное расхождение с Figma повторно проверяется и показывается пользователю; изменение фактов выполняется только после его решения.
- Для воспроизведённого дефекта renderer, workflow или contract owner действует scoped repair из Stage 10 Task 7; факты и HTML-хаки не переносятся в skill.
- Новые письма проходят через модель и renderer. Ручная доводка результата HTML не считается успешным new-build.
- Экспорт и точные format/scale/quality/alpha/crop/display правила берутся из asset contracts и foundation. Существующий MCP-only путь сохраняется.
- Реальные письма, изображения, модели, MCP-ответы и скриншоты не коммитятся в системный репозиторий.
- В папке готовой версии только `email.html` и `images/`; evidence и диагностика находятся снаружи. Исходная версия неизменна, следующая версия увеличивается на `0.1`.
- Тесты и visual regression — локально, делегируются явно `gpt-5.6-terra`, `medium`. Координатор получает краткий итог, не читает полные test logs и не ведёт routine test-fix loops.
- GitHub Actions/PR Checks не запускаются, не читаются и не используются. Если protection технически требует check, сообщить препятствие; не обходить protection.
- Во время реализации — проверки затронутой области. Полный `npm run verify` выполняется перед слиянием на точном финальном коммите кода/контрактов; документационные изменения не требуют полного suite.
- Плановый коммит не начинает реализацию и не разрешает merge. Stage 10 не отмечается завершённым до E2E, merge, exact skill install и clean-chat acceptance.
- Ручной `cupis-active-work-context.md` не обновляется без отдельной просьбы пользователя.
