# NPS/Options: план проверки и исправления области ссылки

> Работа для отдельного этапа реализации. Все задачи ниже ещё предстоит выполнить; текущий PR сохраняет только [диагностику](../specs/2026-10-12-nps-options-click-area-diagnosis.md), этот план и ссылку в состоянии системы.

Цель: вся окрашенная область каждой видимой NPS-кнопки, включая иконку и отступы, ведёт по собственной ссылке. Дизайн, адаптивность, порядок вариантов, изображения и правила заполнения URL сохраняются.

## Граница изменения

Основной файл будущей правки — `scripts/lib/email-interpreter.mjs`. Узкое распознавание владельца NPS и путь HTML кнопки должны использовать текущие факты контракта. Изменение `scripts/lib/email-renderer.mjs` допустимо только если проверка докажет недостаточность уже существующего `output_origin`; не создавать вторую систему происхождения элементов.

Канонические роли `good`, `neutral`, `bad`, action `whole-element`, обязательность `href`, Count и Mobile/Desktop остаются прежними. Публичная модель письма, схемы, Figma, профили доставки, формы, assets и навыки не требуют изменения. Ожидаемые генерируемые изменения — отсутствуют; подтвердить это по актуальному manifest перед реализацией.

Banner/App-Download используется как контроль отсутствия регрессий. Его отдельные выявленные особенности геометрии не исправляются здесь. Banner/Inline и отложенный план PR #127 находятся за границей задачи.

## 1. Закрепить входы и независимые проверки до исправления

- [ ] Закрепить актуальный облачный коммит и разрешить `library-maintenance` для двух компонентов и обоих viewport. Сверить реализацию с диагностикой; при изменении причины обновить план до правки.
- [ ] Материализовать точный локальный снимок и проверить одинаковый lock зависимостей. Не редактировать локальный слепок основной ветки.
- [ ] Сохранить исходные HTML, размеры и снимки Count=2/3 на 320, 360, 600, 720 px. Для итогового сравнения иконок использовать действительные assets; заменитель neutral явно отделять от визуальной проверки.
- [ ] Добавить failing-тесты публичного рендерера в существующую инфраструктуру. Предпочтительно расширить `tests/rendering/nps-options-rounded-controls.test.mjs` и зарегистрированные визуальные сценарии; отдельный файл для browser hit-area допустим, если так устроен текущий runner. Не добавлять зависимость или новый браузерный стек.

Ожидания задавать независимо от `isWholeButtonAction()`, выходной строки или роли helper. В fixture у каждой опции свой узнаваемый URL; проверять назначение, а не общее количество URL. Перед правкой тесты должны воспроизвести отсутствие ссылки на отступах текущего NPS; App-Download должен пройти контроль охвата.

| Проверка | Матрица и критерий |
| --- | --- |
| Полная область | Count=2/3 × четыре ширины; границы `a[href]` покрывают окрашенную кнопку, допустима только округлённость измерения до 0,5 px |
| Фактическое попадание | Центр, края и внутренние отступы каждой кнопки через `elementFromPoint()` достигают её собственного URL |
| Ограничение области | Точки в промежутках и вне кнопок не попадают в NPS-ссылки; одна опция не перекрывает соседнюю |
| Корректный HTML | На видимую опцию одна ссылка в активной viewport-ветке; нет вложенных `a`, одного общего URL на группу, оборачивания таблиц ссылкой или изменения порядка |
| Геометрия | До/после совпадают положение, ширина, высота, фон, radius, межкнопочные отступы и прямоугольники иконок; сохраняются адаптивность и текущие переносы |
| Видимость и URL | Count=2 не выдаёт neutral; скрытая опция или скрытый родитель не выдаёт anchor/assets и не требует URL; видимая опция сохраняет обязательный собственный URL |

В HTML могут присутствовать обе адаптивные ветки. Подсчёт «одна ссылка» относится к конкретной видимой кнопке и ветке, а не к общему документу.

Дополнительные обязательные случаи до выбора реализации:

- [ ] Видимая кнопка со скрытой иконкой: ссылка покрывает весь фон, нет запроса URL/asset для скрытого ребёнка, геометрия берётся из контракта без двойных отступов. Скрытая кнопка целиком исчезает.
- [ ] Разные ссылки и маски видимости Mobile/Desktop: существующая `renderPaired`/`renderSplit` логика сохраняет правильные ветки и их адреса.
- [ ] Набор правил наследования шрифта/line-height, реально встречающийся в письме. Искусственные 32/64 px из диагностики использовать как stress-пробу устойчивости; не превращать их в новые факты дизайна.
- [ ] Пустая внутренняя область и высота из зарегистрированных фактов: нет окрашенного участка вне ссылки. Искусственная высота 84 px остаётся диагностической пробой, без изменения контракта ради теста.
- [ ] Отключённое или не загрузившееся изображение: не скрывать имеющийся alt-текст ради уменьшения line box; тексты брать из существующих данных письма, не спрашивать их у пользователя.
- [ ] Публичный standalone `renderContractTree`, подготовленные/scoped элементы и вложенный NPS в слоте/составном письме. Посторонний компонент с похожей ролью не включает новый путь.

## 2. Выполнить узкое исправление после failing-проверок

- [ ] Ввести приватное распознавание именно владельцев действий NPS: компонент `nps-options`, исходный ID одной из трёх опций, зарегистрированный `whole-element` и `href_slot`.
- [ ] Для подготовленных элементов использовать `output_origin.component_id` и `original_element_id`, уже выставляемые рендерером до scoped ID. Для прямого вызова `renderContractTree` передавать доверенный `component.id` во внутренний контекст и сверять исходный ID. Не принимать принадлежность из произвольного поля модели письма, не определять её только по суффиксу scoped ID или по роли `good`.
- [ ] Сохранить существующее распознавание `button`/`*-button` и общий путь всех остальных контейнеров. Не объявлять любой `whole-element` кнопкой: это может уплощать карточки и блоки с таблицами.
- [ ] Начать с повторного использования текущего `renderWholeButtonAction()` для нормальной NPS-кнопки: одна блочная ссылка владеет внутренними отступами и иконкой; таблица сохраняет текущие фон и скругления. Контрактные значения брать из фактов выбранного viewport, без постоянных 44/54 px в коде.
- [ ] До итогового решения проверить обход ранней ветки пустого окрашенного контейнера для NPS с действием. При скрытой иконке выпускать кликабельную пустую внутреннюю область, учитывая высоту и отступы ровно один раз. Декоративные пустые контейнеры без действия сохранить.
- [ ] Если общий helper не проходит высоту, наследование или disabled-image проверки, добавить минимальный приватный NPS-путь рядом с ним. Ограничить вычисления и inline-стили выбранными опциями; не менять глобально шрифты, высоты или HTML всех кнопок. Зафиксировать измерением, зачем нужен каждый дополнительный стиль.
- [ ] Сохранить alt, размеры и src изображений, существующие атрибуты ссылки, URL bindings и обработку escaping. Не использовать raster всего блока, JS, overlay или дополнительный скрытый URL.

Выбор между безопасным повторным использованием helper и приватной веткой делается по результатам шага 1. Диагностическая замена ролей не переносится в production. Если требуются новая архитектура HTML или изменение публичных контрактов, остановить расширение и отдельно согласовать новый объём.

- [ ] Сохранить проверку круглых NPS-кнопок: фон не переезжает на квадратные родительские `td`; окрашенный радиус и отступы сохраняются. Не исправлять существующее распределение ширин Desktop попутно.
- [ ] Прогнать локально затронутые файлы: `renderer-contract-semantics.test.mjs`, `nps-options-rounded-controls.test.mjs`, относящиеся whole-button сценарии `pilot-fidelity-regressions.test.mjs` и `pilot-email-fidelity-feedback.test.mjs`, `email-instance-visibility.test.mjs`, а также новые проверки области клика.
- [ ] Проверить неизменность action inventory и формы: видимая опция без URL блокирует выпуск; скрытая не запрашивает URL; по-прежнему запрашиваются только недостающие ссылки, тексты не спрашиваются. Расширять тесты формы только при реальном пробеле; реализацию формы не менять без установленной причины.
- [ ] Контрольные рендеры App-Download, обычного CTA и не-NPS `whole-element`/`distributed-cells`: те же области ссылок, текст, размеры и геометрия. Banner/Inline сохраняет текущее поведение.
- [ ] Проверить NPS через публичный путь составного письма с подготовкой scoped ID. Конкретное письмо проверять только на неизменённых локальных входах, не включать его или изображения в PR.

Известная ошибка корневого слота в исходной версии рассматривается отдельно в PR #130 и не исправлена этим планом. Если она блокирует проверку конкретного письма, сообщить зависимость; не обходить валидатор, не переименовывать captured IDs и не смешивать исправления. Standalone и nested fixtures продолжают проверять NPS независимо.

## 4. Выпустить проверенную правку

- [ ] Опубликовать только согласованные renderer/test изменения через облачную ветку PR, затем материализовать точный окончательный SHA. Сверить позволенные пути и неизменность остальных blobs.
- [ ] Делегировать свежие локальные `npm run verify` и `npm run generate:check` на этом SHA: общий интерпретатор влияет на выпуск писем, поэтому итоговая проверка шире целевых тестов. Не запускать и не читать GitHub Actions/PR Checks.
- [ ] Независимый reviewer проверяет исходные требования, действительный diff, связь ссылок с кнопками, маски видимости, все ограничения и результаты локальных проверок. Не считать `PASS` тестов достаточной содержательной проверкой.
- [ ] Обновить диагностику и состояние системы: явно различить выполненные локальные проверки и внешнюю почтовую приёмку. Сохранить локальные receipts с точным SHA и ограничениями.

Исправление считается локально подтверждённым, когда ссылка покрывает каждую видимую кнопку, её адрес правильный, отрицательные проверки проходят, геометрия сохраняется и нет регрессий других действий. Реальные Gmail, Яндекс, Mail.ru и MSO требуют внешней проверки готового письма; без неё `external_acceptance: not-run`. Это ограничение не заменяется браузерными снимками. Слияние требует отдельной команды пользователя.
