# Состояние системы и дальнейшая работа

Этот документ описывает доступные возможности и границы работы. Фактическую версию подтверждает закреплённый коммит GitHub и его `system/manifest.yaml`; локальный снимок нужен только для чтения и проверок.

## Доступные маршруты

| Маршрут | Назначение | Режимы |
| --- | --- | --- |
| `library-maintenance` | Проверить или изменить действующую библиотеку и системные источники | Из `data/workflows/library-maintenance.yaml` |
| `component-onboarding` | Зарегистрировать уже готовый компонент с проверенными источниками | Из `data/workflows/component-onboarding.yaml` |
| `figma-description-sync` | Синхронизировать краткие описания компонентов | Из `data/workflows/figma-description-sync.yaml` |
| `figma-naming-audit` | Проверить названия и выполнить разрешённое исправление | Из `data/workflows/figma-naming-audit.yaml` |
| `system-progress` | Сверить состояние и предложить следующий шаг | Только чтение, с доказательством текущего облачного коммита |
| `email-new-build` | Собрать новое письмо по конкретным макетам | Из `data/workflows/email-build.yaml` |
| `email-continue-fix` | Проверить или исправить конкретное письмо | Из `data/workflows/email-build.yaml` |

Статус конкретного маршрута, его режимы и необходимые входные данные берутся из manifest и workflow. Если маршрут остановлен, он разрешает только обозначенную навигацию; сборка и запись через другой сценарий запрещены.

## Что входит в систему

- Структурированные Mobile/Desktop-контракты, определения типографики, отступов, изображений и названий; машинная проверка их связей и источников.
- Сборка HTML из модели письма, проверка соответствия конкретному макету, браузерное превью и регрессии.
- Выпуск для Альткрафта: единая форма только недостающих ссылок, обязательные служебные вставки, читаемый HTML, изображения, ZIP и текстовые файлы.
- Сохранение выбранной пользователем модели; подбор только поддерживаемого усилия с запасом качества, независимая содержательная проверка и повторное использование однократно сохранённого профиля пользователя и ПК.
- Видимость элементов конкретного письма отдельно для Mobile/Desktop, включая скрытые родители; библиотечная структура сохраняется, скрытое содержимое не включается в выпуск.
- Восстановление среды с проверкой фактического обнаружения навыков, их точных байтов и зависимостей.

Факты дизайна принадлежат Figma и проверенным контрактам. Сохранённые отчёты описывают только собственную область и дату сверки. Непроверенные HTML-проекции не становятся доказанными входами для сборки по наличию записи в реестре.

## Что делать дальше

Следующая работа выбирается по конкретному письму или явно названному изменению системы. Перед изменением фиксируются область, затрагиваемые источники и способ проверки; автоматической очереди на изменение дизайна или создание новых компонентов нет.

Для письма сначала нужны макеты Desktop и Mobile; отсутствующие ссылки на них запрашиваются двумя отдельными полями. После исследования форма запрашивается только для недостающих ссылок видимых действий. Тексты повторно не запрашиваются. Незаданные обязательные URL, в том числе варианты NPS и присутствующие ссылки футера, блокируют окончательный выпуск. Стандартные адреса и формат задают профили доставки, остальные предоставляет пользователь.

Импорт, отправка и отображение в реальных почтовых клиентах требуют результата внешней команды. Пока его нет, `external_acceptance` остаётся `not-run`; локальные проверки подтверждают только свою область.

## Banner/Inline: полная область клика

Сохранены [исследование совместимости](superpowers/specs/2026-10-12-banner-inline-click-area-research.md) и [условный план](superpowers/plans/2026-10-12-banner-inline-click-area-plan.md).

Способ для всей адаптивной `content-area` с живым текстом ещё не подтверждён в Яндекс Почте, Mail.ru и Gmail. Следующий шаг — отдельный образец и проверка его отображения и полной области клика в согласованных клиентах; результаты полученных писем предоставляет внешняя команда. Внедрение в контракт и рендерер начинается после подтверждения способа и отдельного задания. Текущая работа баннера этим документированием не изменена.

Для ответа о состоянии навык сравнивает этот документ, текущий manifest и реальные данные GitHub на одном SHA. Если они расходятся, расхождение сообщается явно и следующий шаг предлагается по фактическим источникам.
