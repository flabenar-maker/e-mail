# CUPIS email-система

Репозиторий хранит структурированные контракты компонентов, общие стандарты, проверяемые foundations, производную документацию и инструменты разработки системы. Готовые письма и их изображения сохраняются только в отдельных локальных рабочих папках.

## Текущее состояние

Структурированные источники — единственная база для дальнейшей разработки системы. Пилот HTML-рендера существует, но сборка произвольного production-письма и автоматическая поддержка Figma-библиотеки пока не объявлены готовыми. Рабочие маршруты временно остановлены в [чек-пойнте](workflows/system-paused.md); наличие записи в manifest не означает разрешения запускать такой маршрут.

[Роадмэп](docs/superpowers/plans/2026-08-25-cupis-migration-roadmap.md) фиксирует порядок этапов. Планы сохраняют историю решений, но не являются входом для текущей сборки письма.

## Источники истины

`system/manifest.yaml` — единственная машинно-читаемая карта источников, маршрутов, навыков и команд. Пути разрешаются через manifest; несуществующий или неразрешённый источник нельзя заменять догадкой.

- Фактический дизайн, свойства и привязки компонентов находятся в Figma. Любая проверка фактов или запись в Figma требует соответствующего MCP-процесса и разрешения на точную область изменения.
- Полные Mobile/Desktop-контракты находятся в [структурированных реестрах](data/components/): `shared.yaml`, `marketing.yaml` и `service.yaml`. Конкретные размеры, отступы, текст, поведение и asset boundaries принадлежат соответствующей записи компонента.
- Общие определения находятся в [foundations](data/foundations/): типографика, отступы, ассеты, нейминг и рендеринг. Design-time правила не заменяют фактическое значение конкретного компонента при сборке письма.
- Нормативные границы заданы отдельными файлами [Core](core/): [контракт компонента](core/component-contract-standard.md), [описание Figma](core/figma-component-description-standard.md), [поддержка библиотеки](core/figma-library-standard.md), [типографика](core/typography-standard.md), [экспорт ассетов](core/asset-export-standard.md) и [HTML-рендеринг](core/email-rendering-standard.md).
- [Полный реестр компонентов](docs/generated/component-registry.md) и другие [generated docs](docs/generated/) собираются из структурированных данных и не редактируются вручную. Реестр показывает все компонентные контракты для чтения и сверки, но HTML-рендерер использует сами `data/components/*.yaml`, а не этот Markdown-файл.
- Figma Description — компактная производная подсказка, а не вход для HTML-рендера.

[Legacy/](Legacy/) временно хранит прежний контур для сравнения и возможного отката. Он не подключён к текущим маршрутам и не считается ни действующим набором правил, ни доказательством завершения миграции; решение о судьбе каждого архивного файла принимается отдельно после cutover.

Проверка конкретного контракта против Figma выполняется свежим read-only MCP-снимком и `scripts/audit-figma-contract-facts.mjs`. Миграционный статус или наличие записи сами по себе не доказывают точность фактов.

## Инструменты и проверки

`npm run generate` пересобирает generated docs; `npm run generate:check` проверяет их без записи. `npm run bundle -- --route <route>` собирает временный контекст выбранного маршрута. `npm run validate` проверяет структурированные данные, связи и собираемость маршрутов. `npm run verify` уже включает `npm run validate` и `npm test`.

Репозиторий остаётся в облачном GitHub. Локальный изолированный снимок точного SHA допускается только для проверок и не становится рабочей копией для правок. В ходе изменений выполняются проверки затронутой области. Для документационных изменений полный набор тестов не требуется. Перед слиянием изменений кода или структурированных контрактов один раз запускается `npm run verify` на точном финальном SHA; после нового коммита финальная проверка повторяется. Windows-специфичные проверки выполняются локально, когда они применимы. GitHub Actions и PR Checks не запускаются и не служат критерием готовности.

## Восстановление среды

«Ознакомься с проектом» означает только чтение текущих источников. «Восстанови рабочую среду проекта» разрешает обратимые действия по [bootstrap-протоколу](bootstrap/README.md). Авторизация GitHub и Figma подтверждается пользователем.

## Навыки и границы

[Навык поддержки системы](.agents/skills/maintaining-cupis-email-system/) маршрутизирует задачи к manifest и действующим источникам, но не хранит копии компонентных правил. Навык сборки конкретных писем ещё не создан. Пока маршруты остановлены, не следует выдавать пилотный рендер за готовую production-сборку.

Новые или изменённые факты компонента сначала подтверждаются в Figma, затем записываются в структурированный контракт и только после этого отражаются в производной документации. Не меняй Figma-дизайн, структуру или названия без прямого разрешения. Не добавляй в репозиторий локальные письма, изображения, архивы или результаты тестов.
